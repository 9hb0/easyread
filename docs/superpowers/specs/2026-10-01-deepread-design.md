# 精读论文文档设计

## 目标

为每篇论文增加一个需要用户主动触发的“精读论文”功能：调用用户在设置中指定的模型和提示词，生成一份不超过 5000 个字符的中文精读文档，并保存在该论文目录中，方便反复查看、复制和下载。

## 已确认的需求

- 每篇论文单独生成精读文档。
- 默认不执行；导入论文、翻译完成、打开论文都不能自动触发。
- 只有用户主动点击“生成精读”后才进入任务队列。
- 生成结果不能超过 5000 个字符，后端必须强制限制，不能只依赖提示词。
- 设置中增加独立的“精读论文”栏目。
- 设置栏目可以选择精读模型，并编辑精读提示词。
- 精读优先使用已翻译的中文内容；未翻译的部分使用英文原文补充。
- 精读模型复用“问 AI”已经配置的模型名单，只保存模型 ID，不重复保存 Key。

## 推荐实现

### 数据与文件

每篇论文目录新增两个文件：

- `deepread.json`：任务状态和元信息。
- `deepread.md`：最终精读文档，生成成功后写入。

`deepread.json` 至少包含 `state`（`idle`、`queued`、`running`、`done`、`error`）、`message`、`updated`、`model`、`prompt`、`chars` 和 `error`。生成失败时保留上一次成功的 `deepread.md`，不覆盖已有结果。

### 模型与提示词

配置文件增加 `deepread` 设置：

- `model`：问 AI 模型名单中的模型 ID；为空时使用问 AI 默认模型。
- `prompt`：用户可编辑的精读提示词。

后端通过现有 `chat_models.engine_cfg` 解析模型配置，因此 Claude、Codex 和 OpenAI 兼容中转站都走已有 Key、BASE_URL 和推理强度配置。用户提示词会与固定约束合并，固定约束包括：只输出精读正文、使用中文、不要超过 5000 字、不要编造论文没有的信息。

### 生成流程

1. 用户在阅读页或文献库对某篇论文点击“生成精读”。
2. 后端检查该论文存在，若已有任务在运行则返回当前状态，不重复排队。
3. 小任务队列执行精读，输入由论文元数据、章节标题、已翻译中文、未翻译段落的英文原文、公式/表格/图题说明组成。
4. 模型返回后做清理和硬截断，最终 `len(text) <= 5000`。
5. 成功时原子写入 `deepread.md` 和 `deepread.json`；失败时只更新状态，不破坏旧文档。

### API

- `GET /api/p/{id}/deepread`：返回状态、元信息和文档内容。
- `POST /api/p/{id}/deepread`：手动触发生成，返回排队状态。
- `/api/config` 的公开配置包含精读模型和已脱敏的精读提示词。
- `/api/config` 保存精读设置时只保存模型 ID 和提示词，不接收或返回 Key。

### 页面交互

- 设置对话框增加“精读论文”栏目：模型下拉框、提示词文本框、5000 字限制提示。
- 阅读页增加“精读”入口，可查看当前文档、生成/重新生成、复制和下载。
- 文献库论文菜单增加“生成精读/查看精读”，方便不进入阅读页也能触发。
- 生成过程中显示排队或生成中状态；生成完成后显示字符数和生成时间；失败显示错误并保留旧文档。

## 不做的事情

- 不在导入或翻译完成时自动生成。
- 不新增独立的 API Key 配置体系。
- 不把精读结果写入 `paper.json`、`discussion.json` 或用户笔记，避免和原文、讨论、笔记混在一起。
- 不要求模型返回 JSON；精读文档直接保存为 Markdown。

## 验收标准

- 新论文不会自动触发精读任务。
- 手动触发后能看到 queued/running/done/error 状态变化。
- 结果文件存在且字符数不超过 5000。
- 重新生成失败时，旧的 `deepread.md` 仍然可读。
- 设置中选择的模型实际用于生成；未选择时使用问 AI 默认模型。
- 自定义中转站模型能沿用已有 BASE_URL、Key 和推理强度配置。
- 模型 Key 不出现在任何前端响应中。
- 现有翻译、问 AI、图片展示和阅读面板功能不回归。
